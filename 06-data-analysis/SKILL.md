# data-analysis

用于发布后的内容数据复盘。核心功能是根据后台数据、互动反馈和创作者体感，判断内容表现、定位问题，并给出下一轮优化动作。

本 Skill 只做数据分析和优化建议，不自动改稿、不生成新选题池、不做平台发布包。

## 触发条件

使用这个 Skill 处理：

- 用户说“帮我分析这条/这批内容的数据”“做复盘”“看看后台数据”
- 用户提供阅读量、播放量、完播率、点赞、评论、收藏、转发、涨粉、私域新增、咨询或成交数据
- 用户提供平台后台截图，需要整理成可行动的复盘结论
- 用户想判断某个选题、标题、封面、脚本结构或发布节奏是否值得继续
- 用户想把发布后的评论、私信和弱关系反馈转成下一轮优化方向

不要用这个 Skill：

- 还没发布内容，只是在找选题 -> 生成选题（`topic-generator`）
- 已选定题目，需要写大纲 -> 内容大纲（`content-outline-builder`）
- 需要做发布前审稿或风险表达替换 -> 内容审稿（`adversarial-content-review`）
- 需要合规审稿或风险表达替换 -> 内容审稿（`adversarial-content-review`）

尽量让用户提供以下信息；缺失时可以先做定性复盘，但必须标注“数据不足”：

| 字段 | 说明 |
| --- | --- |
| 平台 | 小红书 / 视频号 / 公众号 / 抖音 / 其他 |
| 内容链接或标题 | 被分析的单条内容或一批内容 |
| 发布时间 | 便于判断是否已过初步观察期 |
| 内容形态 | 图文 / 短视频 / 长文 / 直播切片 |
| 账号模式 | 认证医生号 / 非认证人格号 / 待确认 |
| 核心数据 | 阅读/播放、完播/读完、互动、涨粉、私域新增、转化 |
| 评论和私信 | 高频问题、情绪反馈、争议点、购买或咨询信号 |
| 创作者体感 | 讲得顺不顺、是否能持续做、制作成本高不高 |

## 分析原则

### 1. 先分清“吸引人”和“留得住”

| 指标 | 主要说明 |
| --- | --- |
| 阅读量 / 播放量 / 点击量 | 选题、标题、封面或发布时间是否把人吸引进来 |
| 完播率 / 读完率 / 停留时长 | 内容结构、节奏、信息密度是否留得住人 |
| 点赞 / 收藏 | 内容是否有价值、是否值得回看 |
| 评论 / 私信 | 是否触发真实问题、情绪共鸣或进一步咨询 |
| 转发率 | 是否具备社交传播价值，视频号尤其重视 |
| 涨粉率 | 是否吸引精准用户，而不只是泛流量 |
| 私域新增 / 咨询 / 成交 | 内容是否完成商业承接 |

### 2. 用组合指标判断问题

| 数据表现 | 说明什么 | 调整方向 |
| --- | --- | --- |
| 播放/阅读高 + 完播/读完低 | 标题或封面吸引人，但正文留不住 | 提高信息密度、前置核心判断、减少铺垫 |
| 完播/读完高 + 点赞低 | 内容不差，但用户没有被引导互动 | 加结尾互动钩子、评论问题、收藏理由 |
| 点赞高 + 转发低 | 用户认可，但传播理由不足 | 提高共鸣度、实用清单感或观点锋利度 |
| 评论多 + 私域少 | 有问题被激发，但承接不足 | 优化评论区引导、简介、免费资料或咨询入口 |
| 播放低 + 互动高 | 题可能窄但用户精准 | 可做系列，不急着放弃 |
| 多次发布仍低播放低互动 | 选题或表达方向可能不成立 | 降级为备选，换角度或停掉 |

### 3. 用 A/B/C 给内容归类

| 类别 | 判断 | 处理动作 |
| --- | --- | --- |
| A 类 | 高播放/阅读 + 高互动 + 有精准反馈 | 继续深挖，做系列延展，复用标题和结构 |
| B 类 | 数据一般，但有单项亮点或明确优化空间 | 改标题、封面、开头、节奏或评论引导后再测 |
| C 类 | 多次尝试仍低表现，且没有有效反馈 | 停掉或换方向，不继续消耗创作力 |

### 4. 不只看平台数据，也看人的反馈

- 弱关系反馈比熟人安慰更接近普通用户。
- 评论区和私信是下一轮选题来源，不只是互动结果。
- 创作者体感也要纳入判断：一个方向数据好但制作成本极高、无法长期讲，不能简单判定为主赛道。

## 输出格式

### 数据复盘结论

| 维度 | 结论 | 依据 | 风险/不确定性 |
| --- | --- | --- | --- |
| 选题吸引力 | 强 / 中 / 弱 | 数据或反馈 | 数据不足时说明 |
| 内容留存 | 强 / 中 / 弱 | 完播/读完/停留 | 数据不足时说明 |
| 互动价值 | 强 / 中 / 弱 | 点赞/评论/收藏/转发 | 数据不足时说明 |
| 精准用户 | 强 / 中 / 弱 | 涨粉/私域/咨询 | 数据不足时说明 |
| 创作者可持续性 | 强 / 中 / 弱 | 体感和制作成本 | 数据不足时说明 |

### 内容归类

| 内容 | 类别 | 为什么 | 下一步 |
| --- | --- | --- | --- |
| 标题或链接 | A / B / C | 简短判断 | 继续深挖 / 优化再测 / 停掉 |

### 优化动作

只给 3-5 条最优先动作，按影响排序：

1. 先改什么：
2. 为什么改：
3. 下次怎么验证：

### 下一步建议

根据复盘结果只推荐一个下一步：

- 需要把 A 类内容延展成新题：生成选题（`topic-generator`）
- 需要把某个复盘结论写成新稿：内容大纲（`content-outline-builder`）
- 需要优化原稿风格：大纲扩写（`outline-expander`）
- 需要把复盘结论转成短视频：口播脚本（`voice-script-writer`）
- 数据不足：补数据

## Guardrails

- 不把单条内容的偶然波动当成长期结论。
- 不虚构平台后台数据；没有数据就明确说“缺少该项数据”。
- 不用“爆了/废了”这类情绪化判断替代分析。
- 医美内容即使数据好，也不能建议用外貌焦虑、疗效承诺或强对比继续放大。
- 复盘只给优化方向，不自动覆盖原稿或发布新内容，除非用户明确要求进入下一阶段。
